# Project module — Agent Guidelines

Root Project aggregate lifecycle, project persistence (IndexedDB and native filesystem), starter templates, musical scale/tuning configuration, missing media resolution, and semantic AI queries (CRDT synchronization belongs to CrdtDocument; version snapshots belong to ProjectVersioning).

## Key Subsystems

- **Project Persistence**: Orchestrates saving, loading, dirty state tracking, and legacy migration across IndexedDB and native desktop files (`useCases/projectPersistence/`).
- **Native Project Files**: Tauri IPC bridge for direct desktop disk I/O (`repositories/nativeProjectFiles/`: `saveProjectToFile`).
- **Template Engine**: Factory templates and starter arrangements with audio preview loops (`useCases/projectTemplates/`).
- **Missing Media Detector**: `stores/missingMediaStore.ts` and `useCases/projectPersistence/helpers/verifyAudioBufferReferences.ts` inspect audio buffer references against loaded clips to flag missing assets.
- **Semantic Project Query Engine**: Structured read interface and creative brief validation for automated agents and AI workflows (`useCases/semanticProjectQueries.ts`, `models/ProductionBrief.ts`).
- **Owner Catalog Discovery**: `useCases/queryAgentDiscovery.ts` answers device, preset, sample, asset and capability discovery as bounded, revision-bearing receipts built only from records other owners publish — their stable ids, versions, evidence and `unavailable` verdicts copied rather than restated. A query this layer cannot answer is `unsupported`; a catalog that exists but holds nothing to read is `unavailable`, and the two never collapse. Capability entries reach it through `agentCapabilityDiscoveryPort`, which the composition root fills from AiRuntime because AiRuntime imports this module and the reverse import would close a cycle.
- **Scala Tuning Parser**: Parses microtonal `.scl` scale files into project pitch definitions (`repositories/nativeTuning/parseScl.ts`).

## Invariants & Traps

- **Single Active Project**: Only one project aggregate is active in memory at a time; project transitions must teardown prior audio graphs and reset dirty states.
- **Transport Quiesced At The Switch**: every project replacement (`newProject`, `createFromTemplate`, `replaceProjectData`) stops the transport before it tears the old project down, but a Play or Record can land during any later `await`, so the check that matters runs inside `resetCrdtProject`, after its last `await` and in the same synchronous turn as the authority switch. `resetCrdtProjectWithTransportStopped` hands it a check built on `isTransportIdle` (CrdtDocument cannot import Transport without closing a dependency cycle), which also reads busy while a take is still closing and while a take has closed that the outgoing project has not saved. A busy transport makes the reset withdraw its durable record and answer `transport-active` without replacing anything; the helper stops playback (awaiting every closing take), saves the outgoing project, tears the audio graph and the external plugins down again and asks again unless the caller's transaction has been superseded meanwhile. The same check also reads the caller's `shouldContinue`, so a load withdrawn or replaced while the reset awaits its durable steps makes the reset refuse and withdraw its begun record, and the helper answers `superseded` without stopping anything: a withdrawal at any point before the switch keeps the session in the open project. Resetting `transportStore` alone would leave the scheduler and engine rolling the old project under a store that reads stopped. A user's Pause or Stop turns the transport idle at once and commits the take afterwards, so idle alone never proves that no take is landing. The repair route obeys the same law at its own boundary: `repairProjectData` stops playback and lands the take's commit before it dispatches, and the handler refuses a transport that is not idle when it executes, because the re-projection releases a take's pending close.
- **A Take That Closes During A Replacement Is Saved Or Reported**: autosave is stopped before the reset, so a take that a stop commits into the outgoing project exists only in memory and the switch is about to replace the document holding it. One rule decides whether the outgoing project owes a save: a take has settled (Transport's `countSettledTakes`) past the count the open project is saved through (`helpers/unsavedClosedTakes`). That count is read in the same synchronous turn as a successful `saveProject`'s snapshot (so Save, autosave and a route's pre-save all count, and a take that lands while a save writes still counts as unsaved), moved up when a `discard` replacement acknowledges the takes, and moved up at the authority switch, because the incoming project owes nothing for the outgoing one's takes. Project owns the count, because saves, discards and switches are Project events and Transport only counts the takes that settle. The rule does not depend on when a replacement began, so a take that a Stop lands after a route's pre-save and during its read (Open Recent, file import) is still saved before the switch, and the pre-save itself (`saveProjectBeforeReplacement`) saves once and never waits for takes or saves again while cycle recording keeps landing them. The helper runs `saveProject` (the Save command's path, so the take's audio is made durable with it) whenever the rule finds a take owed, and a failed save does not hold the switch for the takes it attempted. The user is told with `notifyUser` that the take was discarded only after the reset answers `replaced` and the latest save of the outgoing project failed: a refused reset or a superseded replacement leaves the user in the project with the take intact, and a later successful save keeps a take an earlier one lost. The helper asks `shouldContinue` after the save that precedes the first reset attempt, as it does after every stop and teardown. The replacement still proceeds past a failed save, because the user asked to leave. A replacement that exists to discard the outgoing project (`discardProjectChanges`, the native close dialog's Don't Save, through `newProject` and `loadRecentProject`) passes `outgoingProject: 'discard'`: the helper then acknowledges a closed take without saving it, because `saveProject` would persist every edit the user chose to drop and add a Recent entry, and without telling the user it was discarded, because discarding is what they asked for. Every other replacement keeps the default `save-closed-takes`. A Play or Record in that window also rebuilds the outgoing track strips and wakes its dormant plugins through `ensureTrackStrips`, so every lap of the helper's loop repeats the caller's `resetAudioGraph` and `unloadPlugin`. A Play that is stopped again before the reset asks (Play then Pause inside the unload) leaves the transport idle and is not seen by the check; the strips it rebuilt stay resident.
- **Opening The Open Project Is A No-Op**: choosing the open project's own Recent entry (`isOpenProjectKey`, in the menu and the native `project:open-recent` route) leaves the session untouched, because a reload would read the named save before a closing take's own save lands and hydrate that stale read over the take; reverting to the last save is `discardProjectChanges`, which calls `loadRecentProject` directly and is unaffected. `projectStore` keeps the open project until a pending replacement activates, so the same choice also withdraws every Recent load still saving or reading (`pendingRecentLoads.withdraw`; each route passes `pendingRecentLoads.capture`'s check as `shouldProceed` and re-checks it after its pre-save), leaving the session in the project the user chose last.
- **Dirty Tracking Lifecycle**: Any mutation affecting project state must invoke `markDirty` to ensure unsaved work prompts on unload or autosave.
- **Runtime Detection**: Always check `isNativeProjectRuntimeAvailable` / `isNativeFileSystemAvailable` before issuing native desktop filesystem commands.
- **Scala Tuning Validation**: `.scl` parsing enforces valid pitch ratios/cents and line formats, rejecting corrupted tuning files.
- **One Protected-Scope Source**: `collectProtectedScopes` is the only place that decides which brief entries protect anything, and `isProjectWideScope` the only place that decides what "the whole project" means. Batch admission and `getProjectScopedBriefLock` both read them, so a surface that explains a refusal can never name a lock the guard does not enforce.
