# PluginHost module — Agent Guidelines

Third-party plugin hosting runtime: manages native plugin discovery (VST3, CLAP, AU), desktop IPC bridge, and Faust dynamic DSP JIT compiler.

## Domain Ownership

Owns third-party native audio plugin lifecycle (VST3, CLAP, AU scanning, loading/unloading, native GUI window management, parameter/preset synchronization) and the Faust dynamic DSP JIT compiler. Does not own WebAudio graph nodes or track channel strips (AudioEngine), or device chain models in the arrangement (Arrangement).

## Public Contract Surface

Public surface: `useCases/index.ts`, `stores/index.ts`. The module exports no events or views.

## Key Subsystems

- **`repositories/pluginBridge/`**: Desktop IPC bridge for native plugin host processes (`scanPlugins.ts`, `loadPlugin.ts`, `unloadPlugin.ts`, `openPluginGui.ts`, `closePluginGui.ts`, `setPluginParameter.ts`, `setPluginBypass.ts`, `getPluginState.ts`, `setPluginState.ts`, `onPluginLatencyChanged.ts`).
- **`stores/`**: `pluginScanStore.ts` (discovered plugins, scan paths, progress), `externalPluginActivationStore.ts` (activation status and loaded instances).
- **`useCases/faustEngine/`**: Dynamic Faust DSP WebAssembly compiler and builtin effects (`compileFaustDSP.ts`, `builtinDSP.ts`).

## Invariants & Traps

- **A rejected state restore makes the runtime state non-authoritative**: when a plugin rejects its saved chunk at activation, the instance is marked as a failed restore here, and state capture must preserve the stored project chunk until authoritative state exists again. An explicit `setExternalPluginState` replacement pushes the new chunk to the host through `restorePluginState` and clears the marker only once the host accepts it; a rejected push keeps the marker standing so the next activation retries the replacement from project truth. Reading plugin state never clears the marker (Decision 0003).
- **Capture authority belongs to one native instance generation**: project Save/Export reads through `readExternalPluginStateForCapture`, whose opaque token is invalidated at load, restore, keyed/unkeyed unload, restore settlement, instance forgetting, graph rebuild, session retirement, and whole-runtime clear admission. A caller may accept bytes only while that receipt remains current through its Command commit; a reused string instance id never revives an old receipt. A read that fails on a loaded instance with no pending or failed restore answers `unreadable` with the current token, never a preserve: the stored chunk may lack the instance's edits, so Save and Export must report it.
- **The restore-failure warning is once per failure episode**: `shouldWarnExternalPluginRestoreFailure` records the instance as warned, and every marker-resolve site (restore success, replacement acceptance, unload, graph teardown) drops the warned entry with the marker. A new resolve site must clear both sets or resolved-then-refailed instances stay silently unwarned.
- **Live state crosses an app-initiated teardown through the carry store, never the document**: the removal unload (`unloadPluginCarryingLiveState`, which a created track's Undo also uses), the graph-repair unload, the engine retire, the project-switch unload (`unloadPluginsBeforeProjectSwitch`) and the session-retirement unload (`beginProjectSessionPluginRetirement`'s `retire`) read each instance's live state first, and commit it to `carriedExternalPluginStates` only for the instances actually torn down. The next activation of the same instance id and plugin consumes it once in place of the project chunk; an activation issued while a keyed unload of that instance id is still pending waits for that unload to settle and then activates afresh, so it consumes the carry rather than answering from the instance the unload is about to destroy, unless a later keyed unload of that instance id or a runtime rebuild was admitted while it waited, in which case it answers superseded without loading (Remove, Undo, Redo); that wait is bounded (`PENDING_UNLOAD_WAIT_TIMEOUT_MS`) because callers await activation inside committed actions, and an unload still pending at the deadline fails the activation without loading and leaves the instance to the unload; a read that fails or times out (`TEARDOWN_STATE_READ_TIMEOUT_MS`) warns the user by plugin name, and the instance comes back with its saved state. The read is bounded inside the instance's lifecycle turn as well as at the caller, because the native control-gate wait is unbounded: the deadline releases the read and its lifecycle turn for later TypeScript operations and a rebuild; a plugin hung inside its own native call still holds the native control gate, so a later native unload or retire of that same instance can still block. The project-switch unload runs before the replacement is certain, so it keeps the outgoing project's carries, removal carries included: a refused or superseded replacement rebuilds the outgoing graph from them, and only then warns about the reads it lost, while the authority switch itself drops every carry in its own synchronous turn (`settleProjectSwitchPluginTeardown`), since persisted instance ids return with the next project; its read waits on each instance's lifecycle turn, so a hung plugin can add up to the read deadline to a project switch. The session-retirement unload runs before a window close or quit is certain, so it keeps the project's carries the same way: a cancelled quiesce (`reopen`) rebuilds the graph from them and only then warns about the reads it lost, and only a session that really ended (`release`, after the window is destroyed) drops every carry, silently; its reads run inside the retirement's own rebuild fence, so quit gains at most the read deadline and never waits without bound. Every other whole-runtime unload (a load whose document already switched, through the unkeyed `unloadPlugin()`) drops the carries too; a commit whose read batch started before a drop is discarded, and so is the read of any instance whose carry was written or rejected, or that was activated again, after that read started, because a newer owner of that instance id already decided its carry, though a torn-down instance still loaded without a current read warns, since its live state was destroyed unread. Quit reads plugin state only within that bounded batch.
- **Native scan root security**: Plugin scanner enforces strict platform scan roots (macOS, Windows, Linux default directories). Custom roots require native authorization; symlinks and symlinked ancestor directories are rejected to prevent path traversal.
- **No leaked native handles**: Raw library handles, plugin pointers, and OS window handles stay behind the native desktop boundary; only serializable DTOs and instance IDs cross IPC.
- **Faust synchronization**: Faust is wired in PluginHost and AudioEngine; updates to Faust DSP types or node interfaces must remain synchronized across both modules.
- **External plugins are engine-hosted**: the native engine processes a hosted plugin inline on its own audio callback. No command carries per-block audio across the desktop IPC boundary, and the Web Audio graph holds a unity pass-through where such a device sits.
- **Released strips report back through the sink**: an unload's own chain release changes native strip state with no batch of its own, so `unloadPlugin` forwards the strips it released to whatever `registerReleasedStripReportSink` wired up, and the composition root — never this module — decides who that is.
- **External plugin parameter and tail stores are read-only outside the module**: `externalPluginParameterStore` and `externalPluginTailStore` are exported for reading; their writers stay off the `stores/index.ts` barrel. A reset, an unload or an activation seed retires every parameter re-read issued before it, so a late host answer never lands on a re-activated instance that reuses the id. A tail is kept in frames of the activation rate, never converted here, because both formats' infinite sentinel would not survive a conversion; the load seeds it, `plugin-tail-changed` revises a held instance's only, and forgetting an instance or ending the graph generation drops it. A change for an instance whose load has not returned is held and wins over the load's own figure, because the native host attaches the instance and drains the change once before that answer arrives.
