# AudioEngine module — Agent Guidelines

WebAudio graph runtime: hosts every release-admitted built-in device as a WASM engine node, plus the buffer cache, recording feeds, offline rendering, and latency compensation.

## Domain Ownership

Owns the WebAudio runtime graph (`AudioContext`, track/bus strips, send/sidechain routing), built-in WASM device hosting, sample buffer cache (`stores/audioBufferCache.ts`), audio input recording/monitoring, offline rendering orchestration, and latency compensation. Does not own timeline/clip arrangements (Arrangement), audio export encoding (AudioRendering), warp marker editing (ElasticAudio), or third-party plugin sandbox lifecycle (PluginHost).

## Public Contract Surface

- **`useCases`**: Audio context & engine lifecycle (`initializeAudioEngine`, `getAudioContext`, `audioEngine`, `getAudioTime`, `getEngineState`, `getEngineDiagnostics`, `getEngineHealth`, `isEngineAudioAvailable`, `refreshEngineRtDiagnostics`, `resetAudioGraph`, `resumeEngine`, `waitForDevices`), audio buffer cache (`audioBufferCache`, `cacheAudioBuffer`, `getCachedAudioBuffer`, `decodeAudioFile`, `decodeAudioFileBuffer`), recording feeds (`startAudioRecording`, `stopAudioRecording`, `startInputMonitoring`, `stopInputMonitoring`, `stopTrackInputMonitoring`, `reconcileAutoInputMonitoring`, `suspendAutoInputMonitoring`, `syncAutoInputMonitoring`), Levain zone tables built off the render thread (`buildLevainZoneTables`), device controls (`buildDeviceChain`, `updateDeviceParam`, `updateDevicePatch`, `scheduleDeviceParam`, `scheduleDeviceKeyOn`, `scheduleDeviceKeyOff`), track/bus audio controls (`setTrackGain`, `setTrackPan`, `scheduleTrackGain`, `scheduleTrackPan`, `ensureTrackStrip`, `removeTrackStrip`, `deactivateTrackStrip`, `ensureBusStrip`, `removeBusStrip`, `setSend`, `wireSidechainRoute`), offline rendering (`renderOffline`, `exportStems`, `renderTrackSubgraphOffline`), latency compensation (`getTrackLatency`, `getCompensationDelay`, `getSidechainKeyDelay`, `getLatencyReport`, `reportLatency`), graph compilation & delta (`compileAudioGraphTopology`, `applyRuntimeGraphDelta`, `compileRuntimeGraphDelta`), and handler map `getFinalFeatureHandlers`.
- **`events`**: `AudioDeviceLoadedPayload`, `AudioDeviceRemovedPayload`.
- **`stores`**: `audioBufferCache`, `audioGraphStore` (`defaultAudioGraphState`), `audioRecordingStore`, `adjustmentApplicationStore`.
- **`presentations/views`**: `AudioDevicePicker`, `MidiDevicePicker`, `PluginBrowser`, `PluginScanSettings`.
- **Handler maps**: `getFinalFeatureHandlers`.

## Key Subsystems

- **`engine/`**: Runtime graph nodes (`TrackNode`, `BusNode`, `AdjustmentBusNode`, `AdjustmentLayerRuntime`, built-in WASM device nodes: `BacteriaNode`, `CrumbsNode`, `CrustNode`, `FermenterNode`, `GlutenNode`, `GrandBouleNode`, `GrinderNode`, `KneadNode`, `LevainNode`, `ProofChamberNode`, `ProofNode`, `ScoringNode`, `ToasterNode`), `audioDeviceRuntimeSink.ts`, `wasmDeviceRegistry.ts`, `telemetryAllocator.ts`, `dropoutCounter.ts`. (Device id "Dutch Oven" is the ProofChamber reverb — there is no separate Dutch Oven module).
- **`wasm/`**: Generated JS glue for compiled Rust WASM crates (`crates/{daw-dsp,proof-chamber,scoring,daw-wasm-decoder}`).
- **`worklets/`**: AudioWorklet processors and node wrappers.
- **`workers/`**: Background workers (e.g. Grand Boule Worker behind SharedArrayBuffer ring).
- **`repositories/`**: Audio device selection, recording input streams.
- **`models/`**: `AudioEngineState.ts`, `AudioGraphBackend.ts`, `EngineRtDiagnostics.ts`, `BuiltinDeviceRuntime.ts`.

## Invariants & Traps

- **Audio thread safety**: AudioWorklet and audio rendering threads must never allocate heap memory, block, or take locks.
- **WASM device pipeline**: Device DSP lives in Rust crates and compiles to WASM: `pnpm wasm:all` runs `wasm-pack --target web` for `crates/{daw-dsp,proof-chamber,scoring,daw-wasm-decoder}` into `public/wasm/`. The `scripts/gen-*-worklet.ts` post-processors rewrite the wasm-pack JS glue into `src/modules/AudioEngine/wasm/`, prepending AudioWorklet-scope polyfills and replacing `new URL(..., import.meta.url)` with a static path so Vite does not bundle the `.wasm`. Re-run the `wasm:*` script after changing a crate; never hand-edit files under `AudioEngine/wasm/`.
- **Grand Boule runtime**: Grand Boule runs its live WASM engine in a Worker behind a SharedArrayBuffer ring. Offline render runs the same engine inline in an AudioWorklet, where no live deadline exists. Notes and pedals reach the engine with a sample offset inside the block about to render, in push order, so a scheduled note or pedal lands on its own frame; params are block-rate and apply at the head.
- **Stored controller marks**: a pedal or controller move that Transport posts for stored clip playback carries `stored`, and `discardStoredPedals` (Grand Boule) / `discardStoredCc` (Levain) drop only marked moves still queued, by in-place compaction that allocates nothing on the audio thread. The engine queues otherwise keep posting order within a frame and keep queued pedals and controllers through `allNotesOff`, so the mark is the only way to drop stale stored moves without touching a performer's; a marked frameless move also does not supersede a performer's queued moves of its pedal or controller.
- **Recorded expression curves**: a worklet instrument that voices per-note expression plays a note's recorded `expression` curves in playback and in export, through the one projection both share (`projectNoteExpressionCurves`). Each curve point becomes one `noteExpression` update at the frame the caller's own clock gives the note's projected start plus the point's offset, so a curve keeps its place under a tempo map, a groove, a loop pass and a clip offset. Every update carries the full expression in force for all three dimensions, because an engine reads a missing dimension as neutral and would otherwise reset a bend the note still holds. Offsets count from the note's uncut start: a clip trim or a loop pass that cut the head off leaves the projection segment saying how far into the note it begins (`beatsIntoNote`), so the points the cut passed fold into the value in force at the cut (which replaces the note-on's own expression) and later points keep their absolute positions, as `sliceMidiNoteExtent` re-cuts a note. A point at or after the frame the note's release is posted on is dropped, a point on the start frame replaces the note-on's own expression, and points that share a frame collapse to the last. A Yeast-routed note plays its template's curves on both routes, anchored the same way: live, Yeast sees the note from the clip's head, so the cut it made (`beatsIntoNote` on the note it plays) rides through and the projection adds the cut a later clip boundary makes. Live playback posts each update in the scheduler window whose beat range contains it, so a long note with a dense curve never queues its whole life at once (an engine's live queue is bounded); the engines drop queued `noteExpression` on `allNotesOff`, which is what stops a curve on stop and seek. The track's stored channel pitch bend joins the same projection as `channelBend` (the MIDI module's `projectChannelBend`, injected into the render as `projectChannelBend` because this module may not import MIDI use cases): while a move is in force it is every sounding note's bend and range, a bend in force at a note's start is the note-on's own expression, and a move strictly between the start and the release frame is one more change, so the bend a take recorded out and back is heard in playback and export alike. The engines hold no channel bend (a voice's bend is reset by its own note-on), so there is nothing to return to centre on a stop; an instrument that does not sound pitch bend (`getNoteExpressionDimensions`) is given none.
- **Release census**: The release census covers the complete `public/wasm` tree and every manifest-declared AudioEngine mirror. Package ids and artifact paths come from `scripts/wasm-artifacts.ts`; unknown sidecars, manifest paths, text references, or binary exports fail release validation.
- **Single realm singleton**: The main thread revalidates, fetches and asynchronously compiles each WASM URL once. A short-lived module lease is released on abort or host-construction failure; successful host construction commits one URL per bundle to the `AudioContext`, because wasm-bindgen glue is a realm singleton. Loading another version after that requires a fresh context and is rejected instead of silently retaining the old binary.
- **AudioWorklet instantiation**: AudioWorklet processors receive the structured-cloned `WebAssembly.Module` through `processorOptions`; Grand Boule's Worker receives the same compiled module. A separate port init message starts caught instantiation and the ready/error handshake. Processors call `initSync` and compile nothing on their real-time-adjacent threads. Shared module caching and handshake logic live in `src/infra/audioWorklet/workletInitShared.ts`.
- **Levain bank commit**: a sample reaches the staged bank in three kinds of message, so none copies a whole sample on the render thread: `beginSample` reserves the sample's whole storage inside the engine (the upload's only allocation), each `sampleChunk` copies at most `LEVAIN_SAMPLE_CHUNK_FLOATS` floats into it and allocates nothing, and `sealSample` publishes the sample once every float is there and refuses a short one. The worklet answers each written chunk with `sampleChunkWritten { loadToken, sampleId }` and a refusal with `sampleBankError`; the loader keeps at most `LEVAIN_SAMPLE_CHUNKS_IN_FLIGHT` chunks unacknowledged across every concurrent load (all Levain processors of a context share one render thread, so the budget is one per main-thread realm, shared first come first served, and a load that ends keeps the credits of its still-queued chunks until the worklet has passed them: one per `sampleChunkWritten`, the rest at the first answer that follows them on the port (its `sampleBankError`, its `retiredBankReleased`, or the processor ending), or at once when the port is closed) and stops waiting at once on an abort, a `sampleBankError` for its load or the processor ending, so the worklet's queue never holds a long run of chunks to drain between two render quanta. The engine owns the bound: it tells the worklet where a chunk goes and never offers more than a chunk, and the worklet refuses a chunk that does not fit, belongs to another sample, or runs past the sample before it writes a byte (`src/infra/audioWorklet/levainSampleChunk.ts` is the loader's copy of the figure, pinned equal by a spec; the loader posts each chunk as a transferred copy of its slice, never a view of the cached bank). The worklet reads `memory.buffer` fresh for each chunk, because the reservation can grow it. A sample still open when its load aborts retires with the staged bank. All three are fenced by `loadToken` and answer like the other staging messages ([ADR 0052](../../../.agents/decisions/0052-a-disposed-wasm-engine-drains-in-paced-steps-before-it-is-freed.md)). The render thread never computes a bank's zone tables: the loader has them computed off it by `buildLevainZoneTables` (a Worker running its own daw-dsp instance, the engine's own table code; no fallback, so a builder failure rejects the load, and an abort, the load's `sampleBankError` or the processor ending stops waiting at once and stages nothing, whatever the load's role) and stages them the way it stages PCM: `reserveZoneTables` reserves the LUT, arena and round-robin counters (the staging's only allocation), each `zoneTableChunk` appends at most `LEVAIN_ZONE_TABLE_CHUNK_ENTRIES` LUT or arena entries after the engine checks every one (in order, inside the reservation, a LUT run inside the declared arena, an arena id below the zone count) and is answered with `zoneTableChunkWritten { loadToken }`, paced by the same realm-wide `LEVAIN_SAMPLE_CHUNKS_IN_FLIGHT` budget as the sample chunks, and `sealZoneTables` installs them in O(1) once every entry is written (`src/infra/audioWorklet/levainZoneTableChunk.ts` is the loader's copy of the figure, pinned equal to the engine window by a spec). Every role stages its own tables, because zones are per processor and only PCM is shared. `commitSampleBank` then commits with a call that allocates and frees nothing (the owner publishes its PCM first; a follower holds the commit until the owner's bank publishes); the bank it displaces waits in the engine's retired slot, and so does a staged bank the worklet aborts. The host frees it afterwards with `releaseRetiredBank` messages of one bounded step each (the loader sends the first after `sampleBankLoaded`, or, for a load that failed after its begin, after the `abortSampleBank` it posted, and repeats while the worklet answers `done: false`), fenced by `loadToken`. Each load registers with its port before posting `beginSampleBank`, and the next load holds its begin until every earlier load on that port is over (the end of the release loop, for every load whose begin was posted, whether it committed or not; a load that never posted a begin is over once the loads before it are); the loop also ends when the processor ends, and a load that waits through a processor fault or disposal rejects as "processor ended" and posts nothing. A faulted processor that has not been disposed drops every message except `dispose`, which it answers with `disposed`, and `beginSampleBank` and `releaseRetiredBank`, which it answers by posting its original `error` again, so a load that registers after the fault (the port listener was not yet installed when `error` first arrived) still rejects as "processor ended" instead of waiting for an answer. A `beginSampleBank` that arrives earlier frees the whole leftover bank in one unbounded call, as a safety net only. Wasm memory is private to the worklet's instance, so the release itself still runs on the render thread; it never runs inside the commit or `process()` ([ADR 0051](../../../.agents/decisions/0051-wasm-bank-commit-retires-instead-of-releasing-off-thread.md)). A disposed processor frees nothing in `dispose`: `LevainNode` keeps the port open and sends `releaseDisposedBanks`, one bounded step per message; a disposed worklet, faulted or not, honours only that message and a repeated `dispose` (re-answered with `disposed`) and posts nothing for any other, `beginSampleBank` and `releaseRetiredBank` included; the step releases the retired bank, else retires the sounding one, else frees the emptied engine, and `disposedBanksReleased { done }` answers each. A throwing step leaves the engine unfreed and answers done. The drain ends on done (the engine freed, or poisoned and left unfreed) or when a live AudioContext closes (a completed offline context still answers and drains); a disposed processor posts no `error` during it, so the node's close on one is a defensive stop only. [ADR 0052](../../../.agents/decisions/0052-a-disposed-wasm-engine-drains-in-paced-steps-before-it-is-freed.md) tables every processor answer by state (live, faulted, disposed, faulted then disposed).
- **Crumbs streaming**: Crumbs disk streaming is native-only (`crates/daw-dsp`). Browser playback and offline rendering run the same Crumbs engine in WASM, with decoded PCM preloaded into its in-memory sample pool.
- **Worklet boundaries**: Worklets import nothing from app modules, helpers, or desktop IPC. Depcruise `worklets-no-*` rules match `src/modules/<M>/worklets/**` only; raw processors in `public/audio/worklets/` must be manually isolated. `worker.format: 'iife'` in `vite.config.ts` allows worklet blob URLs to load bundles.
- **Mono clips are dual-mono before the panner**: native is the level reference — it plays a mono source to both outputs and then applies the stereo-input pan law. A `StereoPannerNode` fed one channel applies its mono law instead (−3.01 dB at centre), so the node feeding each strip's panner (`postFaderGain`, live and offline) is forced to an explicit two-channel `speakers` mix via `configureDualMonoPannerInput`. Any new strip that pans must do the same.
- **Single AudioContext**: Exactly one live `AudioContext` app-wide.
- **Faust synchronization**: Faust is wired in AudioEngine and PluginHost; changes in one require matching updates in the other.
- **External plugins are engine-hosted**: the native engine processes a hosted plugin inline on its own audio callback, inside the chain that holds it. The Web Audio graph carries a unity pass-through where such a device sits, so it adds no latency of its own and no audio crosses the process boundary per block.
- **Live topology attach state**: An `external-plugin` device has a native body exactly when the engine reports its instance attached, so the live topology producer takes that attach state as an input (read from PluginHost's parameter store) rather than deriving it from the device. `apply_graph_commands` captures its plugin lookup before mapping and attaches dormant instances behind the fence, so the batch that attaches an instance is always mapped before the engine holds it: binding it takes one further batch. A session start therefore sends its topology a second time when the first batch reports attachments — once, never in a loop, and only while the engine is parked, because a `replaceTopology` batch tears every strip down inside one fence and must never reach a rolling engine.
- **A supplied document is read whole before the render yields**: `captureOfflineRenderInput` and `renderTrackSubgraphOffline` accept a project source from `captureOfflineRenderProjectSource`; with one, every project read comes from it and device setup is captured project-only from each device record, so a device no live instance backs renders from its record alone. Runtime facts that are not document truth — cached PCM, reported device latency, loaded plugin instances, solo mode — stay live, and a device the live session does not hold takes its type's declared latency. Grand Boule's voicing comes from its own chunk, never the live per-device store that may belong to a device the document rewrote; its calibration, which is never project state, is the live device's or, with no store, the one a fresh store starts with. Yeast racks are read live, outside a redirecting reader, because the Yeast adapter rebinds its live rack view on every decode; a caller whose document stores a rack differently must refuse rather than render it, and compares the two undecoded. Every rack read goes through the reader the composition root hands `configureOfflineYeastMidiProcessing` (`getOfflineYeastRackReader` for callers), never the Yeast store: that store subscribes to the track store and registers its CRDT slot when its module loads, so importing it from capture would give every importer of this barrel those side effects.
- **Input monitoring has one runtime owner**: the repository keeps each track's live or pending interest keyed to its input capture, sharing a stream and source per input while owning each listening edge separately. `reconcileAutoInputMonitoring` derives each Auto track's edge from `deriveAutoMonitorEdge` — armed, and the transport stopped or recording; never disarmed, never during playback without recording — and opens or closes it idempotently. Only `audio` tracks open an Auto edge: the microphone belongs to the kinds recording admission captures audio for, so an armed MIDI track never opens it. `syncAutoInputMonitoring` runs it on every track and transport store publication and committed project change, and graph rebuilds and mode gestures call it directly. Recording admission, stop and settle never open or close an Auto edge. `On` admission comes from the explicit gesture, recording admission and graph rearm; a store-only On never requests a microphone. Already-admitted On interests join the same reconciliation and cleanup as Auto interests, for every kind whose Arrangement `getTrackEligibility(...).acceptsMonitoring` capability allows monitoring. Cleanup reads the union of Auto-open records and the repository's admitted live or pending interests, and attempts every affected owner before reporting a cleanup failure. Genuine Off or removal releases the owner, including while held; an ineligible kind, non-audio Auto, disarm, playback without recording or input retarget also fences the old interest as appropriate to its mode. An optimistic absent-track publication retains an owner only while fresh committed truth still makes the same input eligible: On for a monitoring-capable kind, or Auto for an armed audio track while stopped or recording. Permission acquisition is detached from command completion, and an eligible pending grant can settle without attaching or recreating an absent strip; rollback attaches that retained capture only after the current strip returns. Bootstrap binds fresh project readers through `configureInputMonitoringProjectAccess`, and committed changes settle a successful removal even when the visible store does not republish. No track data is retained in that port; a missing registered root owns nothing, and an isolated runtime without a provider applies no committed-owner veto. Project teardown releases outgoing capture owners and invalidates late grants; deferred removal effects recheck the root captured before optimistic publication before each effect, so a missing or replaced root retires outgoing cleanup. A refused open suppresses retries until the edge is closed, a recording starts, the transport comes to rest from playing, or the track passes through On. A grant that settles after `stopInputMonitoring` is a cancellation, not a refusal: the teardown epoch (`readMonitorTeardownEpoch`) tells them apart. A graph reset alone forgets no monitoring records, so an edge adopted or kept through On is still released by a later Off. A rebuild that publishes a transient stopped transport under a rolling one (the runtime-graph repair) holds the owner through `suspendAutoInputMonitoring`: while held the owner still tracks transitions and closes edges but opens none, and it reconciles once on resume, so the pause opens no edge mid-playback. One Stop gesture is one transport publication (`stopPlayback` batches its store writes), because a rolling, not-recording state between `isRecording` and `isPlaying` clearing would close and reopen the edge.
- **A render stops on its own signal without the shared export flag**: `cancelExport` raises a process-wide flag that the mixdown and stem renders read through `checkCancel()` and the segmented kernel's default cancel source. Freeze and bounce (`renderTrackSubgraphOffline`) read none of it and stop only on their own `abortSignal`, so a musician's export Cancel never fails them. A caller that only wants to stop its own mixdown passes `abortSignal` in the render options: the mixdown's checkpoints, track loops and instrument setup read that signal beside the flag, and no other render is affected by it. A user's Stop on an export still raises the flag as before.
- **A stem export outlives the flag it was cancelled under**: the export's settle path lowers the shared flag, but stem tasks still in flight, and the pool starting the next one as a task settles, keep reading the stem set's own scope signal captured at its start (`beginExportCancellationScope`), which stays aborted. A cancelled stem export therefore stops every in-flight stem at its next checkpoint and starts no further stem, whatever a later export has done to the flag.
- **A musician's Cancel reaches only a musician's export**: `cancelExport` raises the flag and aborts the scope only while an export of the musician's holds the render lock, and aborts a queued export's wait whatever holds it. An agent render (measurement or section render) opens no export cancellation scope and sees the flag down for its whole hold; with no render holding the lock a Cancel raises nothing, so no flag waits for a later render. A flag a Cancel raised is lowered in the export's own settle path before it releases the lock.
- **The render lock names its holder, and a musician's export outranks every agent render**: `acquireRenderLock` records whether a musician's export, an agent measurement (`agent-measurement`) or an agent section render (`agent-section-render`) holds it (`lockHolder` in the render options; a render holds it as a musician's export unless it says otherwise). A mixdown or stem export that finds an agent render holding it stops that render through its own preempt signal, never `cancelExport`, waits for its release, then takes the lock; the agent render rejects with a `RenderBusy` error (`isRenderBusyError`) worded for the render that stopped ("measurement" or "render", `agentRenderNoun`), which its caller reports as busy, unless the caller's own stop came first. The wait is bounded by `RENDER_RELEASE_TIMEOUT_MS`, derived from the segmented render's own no-progress watchdog, and an agent render that outlives it fails the export with a message naming that render rather than hanging it. While an export waits, `isExportActive` is true and every other acquire is refused, so a second export still gets "already in progress" and an agent render cannot slip in; an agent render holding the lock leaves `isExportActive` false, because a musician's Export button must not depend on the assistant. Two musician exports, and an agent render against any holder (another agent render included), refuse each other and never preempt. Freeze and bounce take no lock.
- **`audioDevice.removed` means the device left the project**: it is announced exactly once, by `TrackNode` for a device removal, for each id a chain replacement drops, and for each device on a removed track or bus strip, whatever the device's load state. Destroying a device node announces nothing, because the engine also tears nodes down while the device stays in the project: a runtime failure and its recovery, a load timeout, a promotion rollback, a replacement that keeps the id, a strip deactivation (`deactivateTrackStrip`, for a track that stays in the project without a live strip, such as a folder whose last Toaster was removed), and a graph reset. A project switch ends the outgoing devices at its module store reset instead.
- **Unload releases narrow, never create**: `recordNativeChainReleases` is the sink `src/app/bootstrap.ts` registers for PluginHost's own unload releases; it only ever narrows a strip this session's own topology batch already built, because an unload cannot create one.
