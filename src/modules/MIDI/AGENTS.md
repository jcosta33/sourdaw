# MIDI module — Agent Guidelines

Owns MIDI note data, CC/pitch-bend/articulation events, note transform algorithms (quantize, humanize, transpose, legato), chord track events, groove templates, step recording, and WebMIDI hardware input/MPE routing; does not own clip arrangement placement or track strips (Arrangement) or synth audio DSP (Synth / AudioEngine).

## Public Contract Surface

- `stores/`: `midiStore` (`MidiStoreState`), `grooveTemplateStore` (`GrooveTemplateState`, `GrooveTemplateAssignment`, `GrooveConsumerType`), `grooveTemplateProjectRevisionStore`, `chordTrackStore` (`ChordTrackState`), `stepRecordStore` (`StepRecordState`), `webMidiStore`.
- `useCases/`: Note CRUD (`addMidiNote`, `appendMidiNotes`, `batchAddMidiNotes`, `removeMidiNote`, `moveMidiNote`, `resizeMidiNote`, `setNoteVelocity`, `setNoteProbability`, `getNotesForClip`, `setNotesForClip`, `splitMidiNotesAtBeat`), note transforms (`quantizeNotes`, `quantizeNoteLengths`, `humanizeNotes`, `transposeNotes`, `invertNotes`, `retrogradeNotes`, `legatoNotes`, `scaleVelocities`, `strumNotes`, `snapClipToScale`), clip MIDI data (`duplicateMidiClipData`, `glueMidiClipData`, `prepareMidiClipSplit`), chord track (`addChordEvent`, `removeChordEvent`, `moveChordEvent`, `updateChordEvent`, `createChordPitchProjector`, `getChordAtBeat`, `transposeForChordTrack`), groove templates (`createGrooveTemplate`, `extractGrooveTemplate`, `applyGrooveTemplate`, `assignGrooveTemplate`, `previewGrooveTemplate`, `projectClipMidiEvents`), MIDI events (`addMidiCC`, `addPitchBend`, `setNotePressure`, `setNoteSlide`), step recording (`toggleStepRecording`, `stepRecordNoteOn`, `stepRecordNoteOff`, `stepRecordAdvance`), WebMIDI (`initWebMidi`, `selectMidiInput`, `setMidiInputTrack`, `panicLiveNotes`, `triggerLiveNoteOn`, `triggerLiveNoteOff`, `resolveLiveInputNoteReceiver`), file I/O (`readMidiFile`, `downloadMidiFile`), registry (`MIDI_EFFECT_FACTORIES`).
- `events/`: No public domain event payloads exported.
- `presentations/views/`: No views exported (piano roll UI lives in `TimelineEditor`).
- Handlers: `getChordTrackHandlers()`, `getMidiGrooveHandlers()`, `getMidiNoteTransformHandlers()`, `getPatternInstanceHandlers()`, `getWebMidiInputHandlers()`.

## Key Subsystems

- **Note & Expression Model:** Note start, duration, pitch, velocity, probability, and per-note MPE/expression data stored by clip ID.
- **Note Transformation Engine:** Algorithmic manipulations (quantize, humanize, retrograde, invert, legato, scale, strum).
- **Groove Engine:** Non-destructive groove template extraction, previewing, and live dynamic projection (`projectClipMidiEvents`).
- **Chord Track & Pitch Projector:** Harmonic progression model with dynamic scale/chord pitch conforming (`createChordPitchProjector`).
- **WebMIDI & Step Recording:** Low-latency WebMIDI hardware input with MPE channel routing, panic/all-notes-off, and step sequencer recording.

## Invariants & Traps

- **Relative Clip Coordinates:** Notes in `midiStore` are stored with clip-relative start beats (not absolute arrangement timeline beats).
- **Non-Destructive Grooves:** Groove template application dynamically projects note timing without mutating stored note timestamps unless explicitly committed.
- **Recorded Channel Events:** While recording on an armed track, channel controllers (0..119, raw number and 7-bit value, including RPN/NRPN and data entry) and non-member-channel pitch bend are recorded for the recording clip at the beat and in the clip a note-on at that instant gets (`resolveRecordingPlacement`). Every message is kept in arrival order (the CC lane's `addMidiCC` dedups by beat, channel and controller and is for editing only). Controllers owned by a MIDI-learn mapping and MPE member-channel slide and bend stay out. The rows wait in `recordedControllerTakeState`, not in `midiStore`, because each store write reconciles the clip's whole row list and would stall every flush as the take grows. Each carries the id it will hold in the store. `handleCommitRecording.describe` only reads them (`planRecordedControllers`) into its redo snapshot; `execute` writes them in one store write inside the commit's storage transaction (`commitRecordedControllers`), with no undo entry, so a commit that does not land writes nothing (`discardRecordedControllers` drops the buffer) and a message arriving after the write belongs to no take, unless a later take was already recording into the clip when the write landed (its commit waited behind a snapshot transaction): that take's later rows are an overdub, written when it ends. The commit writes no note list: a MIDI clip's stored controllers play, live, on relocation and in export, whether or not it has a note list (a clip without one plays no notes), so a take of controllers alone is audible and a clip derived by split, copy, duplicate or paste that drops an empty list keeps its controllers. A structural placeholder list is never written for playback's sake, because a peer that records the clip's first note concurrently creates its own list at the same key and the merge can drop one of the two. A clip the recorder did not open (an overdub) flushes when the transport stops recording; a discarded take's buffer is dropped unwritten. A new take's rising edge drops what no commit will claim, but a buffer whose opened clip is still on the timeline and uncommitted survives until its commit. A sustain, sostenuto or soft pedal already held when the take begins (`heldPedalState`, read at the transport's recording rising edge) leads the clip's list at beat 0 on its channel, only while it is engaged by the test `isPedalControllerLift` gives stored playback (a switch pedal below 64 holds nothing), unless the take's first pass records that controller and channel at beat 0 itself (a row at beat 0 arriving after a row later in the clip is a later loop pass and stands in for nothing) or the live route would not record it (`admitsRecordedControlChange` is the one admission rule for both, so a pedal a mapping owns is never seeded). A take that ends with a sustain, sostenuto or soft pedal still engaged (its last planned row for that pedal and channel in beat order, arrival order breaking ties at one beat, is not a lift, by the same test, because a loop take overlays every pass into one clip and playback reads the rows sorted by beat) gets a lift row of value 0 in the same plan, because stored playback plays a lift only from inside the clip or on its closing line and the pedal would otherwise stay down past the clip until the transport stops (Cubase writes reset events at a recorded part's end). It sits on the clip's closing line, for a clip the recorder opened (the lift plays as `closesClip`) and an overdub alike, never at the beat the take stopped: a loop take's stop beat is the wrapped playhead, which can fall before a press still held from late in an earlier pass, and a lift there would cancel it. The lift is part of `planRecordedControllers`, so the redo snapshot and the write carry the same rows, ids included. `heldPedalState` is the physical pedal position, so transport stop, pause and seek leave it standing; only an input-device reset or teardown (`resetInputDeviceControllerState`), a change of the input target track (a pedal pressed under another target never reached this one's instrument), and Reset All Controllers clear it. `MidiPitchBend.value` is the signed 14-bit wire delta (-8192..8191, 0 = centre), the same unit as `MidiNote.pitchBend`. Pitch-bend rows written in the earlier 0..127 lane unit are read in the signed unit without migration, deliberately, because issue #3779 rules out legacy-project compatibility and migrations, and no playback or export reads these rows.
- **Live Note Panic Safety:** `panicLiveNotes` must broadcast note-off messages across all 16 MIDI channels to prevent hanging audio synth voices.
- **Hardware Port Reconnection:** WebMIDI input listeners must handle hot-plugged devices and state teardown gracefully.
