# Standing probes: keyboard actions in interactive rows

An interactive browser row fails when its main action is pointer-only, when sibling actions also trigger it, or when keyboard focus is hidden by hover-only styling. Probe native controls, their owning state changes, and rendered focus in Chromium.

## Standing probes

1. **The row's main action is missing from keyboard navigation.** In an imported sample row, require a named native Add button separate from Preview and Favorite. Start at Preview, use real Tab, and assert the button receives focus. Removing the native button or replacing it with a clickable row wrapper must fail the owning component and browser cases. The pointer-only gap was present in `SamplesTab` at `22a84b216658f593391e7e141d90f7c84d13648b`; #6287 later changed the Add route but retained a click-only check, while #6272 named Preview and Favorite in `SamplesTab` without introducing this gap. No introducing PR or assigned review stance is established.
2. **Enter or Space does not make one undoable placement while transport stays stopped.** Use separate fresh imported-sample cases for Enter and Space. Compare complete matching clip objects in raw project authority and its owner projection; require one new `captureUndoHistory()` past action with type `addClip`. Confirm the transport still exposes Play. Real Undo must remove the clip from both authorities, restore the prior past length, and move `addClip` to future. Removing or duplicating the Add handler, or allowing the key to toggle transport, must fail its case (#6287).
3. **Preview or Favorite also triggers Add.** In separate fresh cases, activate Preview and Favorite through their own native controls and compare project clips and Undo history before and after. Preview must only preview; Favorite must only change favorite state. Dispatching Add from either sibling action must fail the component case (#6287, #6272).
4. **Focused actions have no visible focus paint after the pointer leaves.** Keep focus within the same row, move the pointer outside it, and reach Add then Favorite with real Tab. Compare a one-pixel inside border strip on Add before and after focus with finite CSS transitions disabled; the captured PNG bytes must change. Require Favorite's resolved opacity to remain visible while focused and retain its focused screenshot with transitions disabled. Removing the inset ring or focus-within visibility must leave the relevant paint or opacity unchanged and fail the owning case.
5. **The native Add control breaks pointer click or drag.** Use independent fresh imported-sample cases: click the visible sample name and require one placement; then start a native drag on the Add button and drop on the current audio track's actual timeline row, requiring one canonical raw/projected clip and one `addClip` Undo action. Keep the existing component assertion for the full drag payload. Removing the Add click or breaking dragstart on the row must fail its corresponding case (#6287).
