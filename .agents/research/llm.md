Implementation Guide: Local-First Deterministic LLM-Driven DAW EditingThis document establishes the technical architecture and implementation strategies for integrating a 7B-class LLM into a Digital Audio Workstation (DAW). The framework focuses on guaranteed structural integrity, semantic correctness, and low-latency streaming across browser (WebLLM) and native (mistralrs/Rust) environments.1. Project State Representation: The EASE AlgorithmLLMs generate tokens in a linear, left-to-right fashion and lack an internal syntax checker to manage deep nesting or sequential arithmetic. Standard project formats like DAWproject XML are unsuitable for direct LLM context due to their hierarchical depth and array-based nature.Normalization and FlatteningTo maximize model accuracy (which drops 15–25% with every level of JSON nesting beyond three), the project state must be normalized into a relational structure of flat collections.Logical State Summary: Omit granular MIDI notes or automation points from the global prompt. Provide only the "Logical State" (track headers, plugin chains) to preserve the attention budget.Selective State Injection: Inject full-fidelity clip or automation data only when the user query explicitly targets those entities.Explicitly Addressed Sequence Encoding (EASE)Traditional array-based JSON suffers from index drift: removing track causes all subsequent indices to shift. 7B models frequently miscalculate these shifts, leading to "incorrect tool invocation" on the wrong target.Implementation: Replace positional arrays with key-value mappings using unique, stable two-character identifiers (e.g., "ax", "by").Result: Dual order-invariance. Element storage and operation execution become order-independent, reducing token usage by ~31% while maintaining edit quality within 5% of full document regeneration.2. Edit Representation: Hybrid DSO-Patch CompilationThe system follows a hybrid architecture: the LLM acts as a high-level "planner" outputting Domain-Specific Operations (DSOs), which the Rust backend then "compiles" into atomic RFC 6902 JSON Patches.DSO Design and SafetyDSOs (e.g., duplicate_clip) abstract away pointer path construction, which is a high-entropy task where LLMs frequently hallucinate.Strict Typing: Deserialized JSON is mapped into strongly-typed Rust structs using serde.Precondition Guards: Every patch must begin with a sequence of RFC 6902 test operations. If the user modifies a track volume while the LLM is generating, the test op fails, triggering a Semantic Rebase rather than applying a corrupted edit.Inverse Patch GenerationTo support bit-perfect undo functionality, the backend compares pre-edit and post-edit states to generate Inverse Patches.Logic: For a replace op, the inverse is a replace with the old value. For an add, the inverse is a remove.3.
